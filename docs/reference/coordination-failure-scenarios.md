# Сценарии отказа координации и границы монополии

Обновлено для wire v2/0.3.0, 19.10.2026. Историческая база реестра — решение
владельца 16.10.2026, master 6b9174571f2f266b761cdcb1b95cad742fd41027/0.1.2.
[Текущий протокол](leader-election.md), [учёт и статистика](orchestration-risk.md),
[решения v2](../history/2026-10-19-monopoly-protocol-v2.md).
Исторические отчёты сохраняются; их роли R1/R2 не описывают текущий runtime.

## Как пользоваться реестром

Принятые остаточные риски наблюдаем и дорабатываем при слишком частом
эксплуатационном проявлении; численный порог не задан. Они не требуют
повторного архитектурного обсуждения по каждому эпизоду. При этом новые
причины нарушения и ослабление защит запрещены: совпадение результата
«два владельца» с историческим риском не означает принятия новой причины.
Проверять участников, предпосылки и порядок операций, сохранять воспроизведение.

Статус «защищено v2» означает обязательную защиту внутри условной модели,
а не доказательство свойств реального API. «Граница» — допущение гарантии;
«остаточный риск» — принятый внешний/временной путь; «доступность» — отказ или
ожидание без выдачи двух прав. Несколько кандидатов/pending/Busy не равны
двум монополиям. Split-brain лидерства и пересечение физических воздействий
учитываются отдельно. Два допустимых владельца одного прибора — уже нарушение,
даже без команд. Unknown не превращается в безопасный эпизод или конфликт.

## Известные пути конфликта

| ID | Историческая причина | Сопоставление с v2 |
| --- | --- | --- |
| R01 | Исполнитель переносил старый header лидерства в общий request-регистр; откат seq/token/FREE и ABA | **Защищено v2:** исполнитель пишет только notes/R2 без лидерства, лидер/кандидат только name/R1. Новый record_id каждой записи. Старый stale-header контрпример сохранён как исторический, не допустимое расписание v2. |
| R02 | Восстановленные R01 разные лидеры подтверждали себя и выдавали конфликтующие grants во второй строке | **Защищено v2 в модели:** устранена общая запись header; Fischer W=2Delta, исходные bounded окна/guard, renew-before-grant и horizon. Две строки не стали CAS. Иная новая причина двух выдач — регрессия; выход за модель относится к R04/R06. |
| R03 | После admission меняется лидер/grant, старая команда ещё доставляется; нет fencing | **Остаточный риск:** кешированный grant действует до исходного expiry; чужая смена роли его не отзывает. Интервалы разделяет command_guard, takeover ждёт старую аренду и карантин. Пауза после последнего guard и хвост сверх Delta_cmd остаются границей. |
| R04 | Пауза/сеть/сервер увеличивают окно или запись впервые применяется после timeout | **Граница:** исходный OperationWindow, per-call cap, freeze перед каждой R1 записью, проверка полного ответа и потеря роли. Late apply — out_of_model, исключён допущением, но не доказанно исключён API. Отправленный HTTP не отменяется. |
| R05 | Часы выходят за rho, snapshot/клонирование старого процесса | **Граница:** CLOCK_BOOTTIME без fallback, фиксированная epoch-привязка, ступенчатый rho, причинная проекция nonce. NTP после snapshot не влияет. Для истечения лидерства принята абсолютная попарная погрешность не больше Delta; запас max(Delta профилей) проверяется на READ send. Выход за абсолютный допуск/rho и восстановление снимка вне модели. |
| R06 | Нелинеаризуемый сервис, stale read, неверная семантика записи | **Граница:** атомарность/линеаризуемость/независимость полей — допущения, readback их не доказывает. Неизвестные данные не FREE. Натурная проба не устанавливает серверных гарантий. |
| R07 | Прямой ЛК или клиент без протокола меняет устройство/метаданные | **Остаточный риск:** ЛК сохранён по решению человека. Индикация grant в name/R1 не блокирует его. Новым штатным алгоритмам обходить executor запрещено. |
| R08 | Повтор идентичности/nonce/token либо коллизия | **Граница и защита:** все ID UUID, fresh term/record/clock, revision — счётчик. Память ключей всего срока и handled_request предотвращают переобслуживание; старый term не возобновляется. Коллизии/snapshot исключены, намеренный reuse запрещён. |
| R09 | Принятая перед expiry команда действует после него | **Остаточный риск:** reserved_until=valid_until+K(Delta_cmd)*Delta_cmd, двухслотовое продвижение и карантин. In-flight завершается, grant не продлевается. Хвост измеряется от admission, не HTTP RTT; физическая граница пока unknown, Delta_cmd=5 с unmeasured. |

Исторический порядок R01/R02 и полная шкала остаются в
[модели v1](../reports/2026-10-14-two-register-coordination-review.md).
Исполнитель v2 не имеет capability записи R1, поэтому этот порядок не
переносится на v2 автоматически. Timeout после send по-прежнему означает
неизвестный исход без слепого повтора; неизвестность не восстанавливает роль.

## Выбор, продление и передача лидерства

| ID | Сценарий | Поведение v2 |
| --- | --- | --- |
| L01 | Конкурирующие кандидаты читают FREE | Fischer W=2Delta и точный readback, bounded окна. Справедливости/времени победы нет; до подтверждения роли нет. |
| L02 | Продление/новая запись сбрасывает наблюдение | Любая новая полная R1/record_id начинает консервативное наблюдение заново. Живой лидер ограничен своим term. |
| L03 | Crash/kill/штатная остановка лидера | Естественное истечение R1, без раннего FREE. Кандидат ждёт абсолютный leader_until плюс max(Delta профилей) и при смене профиля прежний физический хвост. Просроченная запись не требует наблюдения полного периода; остаются poll/HTTP/W/карантин. Ограниченный запрос не гарантирует takeover; после bootstrap возможен новый запрос в том же приложении. |
| L04 | LeaseLost/unknown/неподтверждённое renewal | Роль прекращается; поздний ack её не возвращает. Уже подтверждённый grant сохраняет исходный локальный интервал, finally не отменяется. |
| L05 | Предел непрерывного срока 20 минут | first_send+1200/K(1200), без сброса renewal. Далее только новые выборы/term_id. |
| L06 | Смена лидера и старые grants | Старый horizon обязан покрывать grant_until+Delta; кандидат ждёт абсолютное окончание старого лидерства с запасом на рассогласование часов, при смене профиля также прежний физический хвост. Дополнительный карантин новой роли сохранён. Проекция grant остаётся причинной; кешированный grant не отзывается одним несовпадением текущего лидера. |
| L07 | Потеря ack при прежнем освобождении FREE | Путь раннего FREE удалён: release только останавливает продления. Неизвестная запись не повторяется; late apply — R04/R06. |
| L08 | Невыполнимый период/неверный профиль | Проверка P>=8Delta, операций/W/карантина/stop-margin и общего предела; grant не расширяет период. Неизвестный mismatch без записи; известный A→B только с полным previous_profile и ожиданием по A. |
| L09 | Повреждение/усечение/неизвестный формат/переименование | Отказ, не FREE; проверка UTF-8 capacity/точного префикса/readback. v1 не поддерживается, автоматической очистки нет. |
| L10 | 429/ошибка/недоступность API | Отказ/unknown/потеря роли, без обхода проверок. Отказы и потеря покрытия учитываются отдельно. |

## Заявки исполнителей и последствия для отопления

| ID | Сценарий | Поведение v2 |
| --- | --- | --- |
| A01 | Конкуренция и потеря request/heartbeat/finish | Однопозиционная R2, известное вытеснение повторяется с прежним nonce/backoff. FIFO нет. Молчание не отзывает grant; replay лидерства исполнителем невозможен. |
| A02 | Crash после request до получения/использования grant | Неиспользуемая бронь живёт до reserved_until. Словарь ключей всего срока, handled_request при takeover и отказ старого term запрещают повторную выдачу старого nonce. |
| A03 | Ack/release потерян или другая revision | Точное сопоставление ID/nonce/revision и причинный sample. Неизвестный release не повторяется; резерв не сокращается. Смена текущего term не отбирает уже кешированный grant. |
| A04 | Потеря локальной idle-session до возврата handle | Истечение по исходному lease при следующем acquire/drain. Acquisition, принятые команды и pending/running release ждём до конца. Unclaimed не раскрывается caller, cleanup не пишет чужую строку. |
| A05 | Слишком короткий lease, off/finally после expiry | Ошибка без команды; достаточный бюджет всей секции — ответственность алгоритма. Будущий grant остаётся REQUESTED; очередь не продлевает timeout/lease. |
| A06 | Kill/потеря питания во время импульса | Finally не гарантирован. Expiry восстанавливает возможность управления, не нагрев. Watchdog/журнал восстановления не вводятся. |
| A07 | Ручной on во время импульса | Не отменяет finally off. Изначально включённый сброс алгоритм не трогает; человек принимает риск ЛК. |
| A08 | API принял команду, нагрев не восстановился | API-успех/readback не доказывает физического завершения. Без отдельного источника physical_tail=unknown. |
| A09 | Нет/неполная статистика/сломался sink | Никаких повторов команд ради статистики; partial не доказывает безопасность или частоту. |

Индикация в name/R1 может сохраняться после завершения секции до конца
резерва/срока; её читают по grant/интервалам. Это не доказательство автора
команды, исключительности или блокировки ЛК.

## Новые нарушения, которые запрещено добавлять

| ID | Обязательная защита |
| --- | --- |
| C01 | Своя identity/session/прибор и действующий локальный интервал в admission. Общий executor; finally не получает исключения после expiry. |
| C02 | DENIED/cancelled/expired запрос не раскрывает unclaimed-session через immediate/reuse. GRANTED и issued атомарны, cleanup/in-flight защищены. |
| C03 | Исходные timeout/lease неизменны; GET/retry не обновляют sample. Память всех обработанных ключей срока плюс маркер R1; новый term требует свежего nonce pending. |
| C04 | Локальная reservation живёт до конца acquisition/принятой команды/первого release и его выполнения. Распределённый резерв — до reserved_until даже после finish/cancel/expiry. |
| C05 | Shutdown сначала drain, затем workers/transport; LeaseLost не отзывает действующий кешированный grant/finally. Bounded close не сообщает ложный успех. |
| C06 | Только лидер/кандидат пишет R1=name, только исполнитель R2=notes; W/наблюдение/карантин/guard/horizon не сокращаются. Нет внутрипроцессного обхода и раннего reuse слота. |
| C07 | Unknown/повреждение не FREE; неизвестный эффект не повторяется. Fresh UUID, новый term после restart; все R1 записи через исходный bounded guard. |
| C08 | Одна локальная синхронизация выдачи; закрывающийся владелец не перезапускается. Статическая граница coordination и роли не обходятся новыми фасадами. |

Новая причина либо нарушение C01–C08 исправляется при разработке без ожидания
частоты. Принятый остаточный риск требует фактов и сопоставления причин,
а не молчаливого расширения реестра. Версии, normal/fault, runtime/simulation
и partial/complete анализируются раздельно; polls не увеличивают число
эпизодов монополии. Запись этого документа не выполняет запросов ZONT.
