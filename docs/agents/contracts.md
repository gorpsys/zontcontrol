# Контракты приложения

Этот файл описывает текущий код. [Целевая архитектура](architecture.md)
отдельно задаёт управляющий API v1, DI, регистратор и жизненный цикл будущих
автономных модулей. Их здесь не объявляем уже реализованными.
Контракты прототипа не являются обязательствами совместимости: при выполнении
плана старый клиент удаляется, а потребители и тесты переходят на API v1.
Свойства данных и калибровка детектора остаются основанием новых проверок.

## Слои

`client.py` выполняет HTTP с явным таймаутом; `inventory.py` и `history.py`
нормализуют данные; `anomaly.py` принимает пригодные временные точки;
`monitor.py` строит разовое решение; `commands.py` подготавливает команды;
CLI выбирает действие и форматирует результат. Обнаружение не отправляет
команды. Исследовательские скрипты не подменяют рабочий клиент.

## Чтение и время

Значения связываются по ID прибора, контура и датчика. target_temp и
setpoint_temp берутся из выбранного контура. Тип consumer не доказывает
регулирование по воздуху. Скрытый контур возвращается API, но не заменяет
контур регулирования. null не равен нулю. Время хранения и передачи — UTC,
RFC 3339; пояснения владельцу можно давать по Москве.

fetched_at — получение ответа, не измерение. История использует реальные
метки времени; будущие значения и линейная интерполяция запрещены для
принятия решения. Сокращённая история, пропуски, неверный датчик и неизвестный
сброс учитываются явно. worktime — запрос автоматики, не доказательство пламени.

## Разовое обнаружение

Основной сценарий — новое независимое решение по последним 45 минутам.
Не требуется сохранённого инцидента или предыдущего запуска. Физический
отказ и confirmed_pattern различаются: последний означает температурный
паттерн. normal не гарантирует исправность; unknown не превращается в false.
warning и confirmed_pattern дают anomaly=true, suppressed/normal — false,
unknown — null. Старое событие в окне не определяет текущее решение.

Намеренное отключение выполняется через «Сброс котла». Состояние true —
котёл отключён; false — включён. Учитываются короткие импульсы между
температурами и пять минут после реального переключения. В историческом
архиве до 27.09.2026 23:36 Москва сброс OFF по указанию владельца.
Этот факт не переносится автоматически на неизвестные приборы и периоды.

Параметры SMART 2.0 — в detection_profile.py. Калибровку сохранять отдельно
от кода: границы эпизодов, происхождение меток, исследованную сетку,
неизвестные данные, предупреждения и задержки. Проверка на том же архиве
не считается независимой валидацией будущих отказов.

## Команды

prepare_command и apply_command по умолчанию не выполняют сетевых эффектов.
execute=True/--execute — явная отправка после проверки актуального списка,
связи, команды, типа элемента и диапазона. Зависимый контур нельзя менять
как самостоятельный. set-temp переводит контур в ручной режим.
Чтение setpoint_temp не означает наличия метода его прямой записи.

После таймаута команды неизвестно, выполнена ли она. Автоматического
повтора управляющих запросов нет; сначала прочитать состояние и проверить
прибор. Прямая отправка HTTP в обход клиента не заменяет реализацию команды.
Автоматическое восстановление после аномалии пока не реализовано.

## Секреты

ZONT_TOKEN поступает из окружения; получение нового токена — отдельная
интерактивная утилита с закрытым вводом пароля. ZONT_CONTACT — контакт для
X-ZONT-Client, не обязательно логин. Не выводить секреты и произвольные тела
ошибок API. Облачные секреты планируются в Yandex Lockbox.
