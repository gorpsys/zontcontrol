# Разработка

## Где что лежит

| Путь | Назначение |
| --- | --- |
| zontcontrol/ | Устанавливаемый Python-пакет и CLI |
| tests/ | Офлайн-тесты unittest на синтетических данных и подставных ответах |
| scripts/ | Сбор данных, исследования и инструменты разработки |
| docs/reference/ | Подробности API, форматов и действующего алгоритма |
| docs/agents/ | Контракты и инструкции изменения кода |
| docs/history/ | Решения и основания выпусков |
| docs/plans/ | Будущие работы с явным статусом |
| docs/reports/ | Отобранные итоговые отчёты для документации |
| deploy/ | Шаблон будущих параметров облака, без секретов |
| reports/ | Локальные архивы, графики и результаты экспериментов |
| build/, dist/ | Результаты сборки, вне Git |

Сохраняется существующее расположение пакета, чтобы python3 -m zontcontrol
работал из checkout. Переезд в src/ сейчас не нужен.

## Документация

README объясняет установку, токен, чтение, разовую проверку, предпросмотр,
отправку и действия при ошибках. Он описывает только то, что работает сейчас.
Технические команды, CI, сборка и выпуск — scripts/README.md. Подробные
схемы и протоколы — docs/reference. CHANGELOG краток, по версиям; причины
и объединение PR — docs/history/versioning.md. Планы не выдавать за реализованное.
AGENTS.md содержит основные правила и ссылки, без хроники всех сессий.

Исходные архивы ZONT и массивные сгенерированные результаты остаются в
reports и не публикуются по умолчанию. Отчёт для docs/reports выбирается
и проверяется отдельно. Старые локальные пути сохраняются: исследовательские
скрипты используют их. reports/early-detection-algorithm.txt — указатель
на канонический справочник, не второй редактируемый экземпляр алгоритма.

## Проверки

Runtime — Python >=3.11 и только stdlib. Make использует .venv/bin/python,
если он есть, иначе python3. make lint проверяет синтаксис, пробелы,
локальные Markdown-ссылки и метаданные проекта; полноценный сторонний
линтер пока не подключён. make test — unittest. make check — обе проверки.
make package — wheel через setuptools>=68, без runtime-зависимостей.
make package-check проверяет smoke установленного wheel вне checkout.
Для офлайн-сборки заранее нужны setuptools>=68 и wheel; это build tools,
не зависимости приложения. Состав и запуск — scripts/README.md.

Потоковые тесты синхронизируют проверяемые этапы через Event/Barrier.
Новый запуск проверяется по новому экземпляру модуля и отдельному Event отмены;
UUID и идентичности участников управления приложению больше не нужны.

GitHub Actions проверяет PR и master: Lint и Offline checks на Python 3.11/3.12.
Offline checks до сборки/установки пакета запускает scripts.release_version:
литерал __version__ совпадает с первым разделом CHANGELOG, номер выше тегов
и версии базы PR даже при задержке предыдущего задания публикации.
На master повторный check допускает аннотированный тег только на том же SHA.
Checkout закреплён на github.sha; PR не получает права записи.
Никаких ZONT-токенов для CI не требуется. При настройке защиты master
потребовать оба checks на актуальном SHA, запретить обход для администраторов;
публикация через PR. Локальных успешных тестов недостаточно для подтверждения CI.

У ZONT нет настроенной изолированной песочницы: торговый Sandbox E2E
autorepeater не переносится. Тесты транспорта используют подставные ответы.
Облачная и физическая приёмка добавляются отдельно, без автоматического
включения реального сброса. Поведение, изменяющее отопление, проверять в
пределах согласованного владельцем сценария.

## Версии

Версия — литерал __version__ в zontcontrol/__init__.py. Setuptools получает
его через dynamic attr, без отдельного номера в pyproject.toml; CLI и wheel
показывают один X.Y.Z и без Git. Автоматического .dev/dirty-суффикса нет:
номер сам по себе не доказывает чистоту checkout или опубликованный выпуск.
--version у zontcontrol и zontcontrol-get-token (также через python -m)
не требует токена и сети. Старый zontcontrol-control удалён.

Выбор MAJOR/MINOR/PATCH, обновление CHANGELOG, проверка Git после коммита,
публикация и повтор workflow описаны в единственной
[процедуре выпуска](../../scripts/README.md#версии-и-выпуск).
make lint сверяет локальные метаданные без Git.
Изменение тонких порогов детектора может быть PATCH при сохранении контракта
решения, но смена смыслов anomaly, обязательных параметров или правил
управления требует отдельной оценки совместимости и описания перехода.
