# Yandex Cloud: план запуска

Статус: подготовлен выпуск 0.5.0, premerge checkpoint; обновлён 20.10.2026.
Актуальная постановка —
[запрос владельца](20261020165020-yandex-cloud-boiler-reset-request.md),
работа — [подробный план](20261020165020-yandex-cloud-boiler-reset-implementation-plan.md),
операции — [проверенные команды yc](20261020165020-yandex-cloud-yc-commands.md).
Облачный handler/ZIP/workflow реализованы и проверены офлайн. Отдельные
ресурсы, IAM/OIDC и metadata активной версии секрета подтверждены:
[отчёт provisioning](../reports/2026-10-20-yandex-cloud-provisioning.md).
Первый deploy, таймер и два плановых запуска ещё не выполнены.

Новый план заменяет прежнюю дорожную карту: функция выполняет настоящий
boiler_reset once раз в 15 минут; folder/bucket/federation/runtime SA/invoker
переиспользуются из образца, а функция/deploy SA/OIDC-привязка/секрет z_token
созданы отдельно. Таймер создаётся только после заполнения секрета,
первого успешного деплоя и отдельного подтверждения владельцем его создания
и включения. Каждая ручная команда yc предварительно согласуется.
Слияние PR требует отдельного разрешения владельца.

Повторы — как у образца: один повтор таймера через 10 секунд после ошибки;
--async-max-retries у версии функции явно не задаётся. Повтор выполняет
весь once; отдельные команды котлу автоматически не повторяются.

Текущий [контракт деплоя](../agents/deployment.md) отражает принятые решения.
Детектор и профиль не меняются, синхронизация не
возвращается; CLI/continuous остаются локальными.

Историческая основа соглашений —
[autorepeater PR #36](https://github.com/gorpsys/autorepeater/pull/36).
Для нового плана проверен актуальный master образца, а не только этот PR.
