## 2. Разовая облачная оценка

Добавить handler.handler с явными параметрами прибора, контура, датчиков,
контакта и таймаута; ZONT_TOKEN получить из env, связанного с Lockbox.
Вызов нового детектора по последним 45 минутам, без хранимого состояния и
управляющих запросов. Неверная конфигурация проверяется до обращения к ZONT.
Определить результат и безопасные ошибки; не возвращать секреты.
Тестировать handler с подставным клиентом и неизвестными/свежими данными.

Добавить scripts/build_yandex_archive.py и make yandex-archive:
build/yandex-function.zip. Allowlist включает пакет, handler и manifest
SHA/версии; локальные архивы, tests, токены и окружения не упаковываются.
Зависимостей runtime нет, установка из PyPI при запуске не нужна.
Проверить импорт архива в изоляции без ZONT_TOKEN и без API-запроса.
Добавить Cloud package check в CI и защиту master.

управляющих воздействий, если такая функция будет добавлена позднее.

## 4. Автоматическое восстановление

Архитектура определена в [отдельном контракте](../agents/architecture.md):
boiler_reset — once/continuous, только текущее confirmed_pattern допускает
импульс 40 секунд; сам алгоритм в finally немедленно выключает сброс
при штатной остановке/исключениях. Для once boiler_reset рекомендован запуск примерно раз в 15 минут,
без отдельного учёта повторных попыток между вызовами. Правила модуля —
[здесь](../reference/boiler-reset.md). Журналы, watchdog и независимый исполнитель
не добавляются; смерть host и жёсткое завершение runtime вне гарантии.
Решение №7 закрыто: прямой ЛК остаётся доступен с ответственностью человека
и принятым риском. Занятость по grant видна в name/R2 с исходным префиксом;
это не блокировка ЛК, ручной on не отменяет off из finally.

Постоянный CLI и continuous не запускаются бесконечным циклом внутри
Cloud Functions. Для них нужен локальный host или долгоживущий контейнер/VM;
scheduler функции выполняет повторные once. Плановые 60s read-only функции
не достаточное основание для бюджета чтение + импульс 40s + выключение.
Внутренний таймаут и штатное завершение должны оставить время на finally
до жёсткого timeout платформы; аппаратного восстановления после kill не обещается.
Локальное автоматическое восстановление реализовано и проверено офлайн;
перенос этого сценария в облако и физическая приёмка — будущая работа.
Новая команда после истечения аренды, включая finally, отклоняется;
принятые ранее завершаются. LeaseLost координатора не отзывает сессию алгоритма.
Риски R1/R2 приняты со сбором статистики; строгая безопасность и достигнутые
99.9% не заявляются. Для облака сохраняются фиксированные config-файлы,
собственные схемы модулей и отсутствие общего execute-флага boiler_reset.
