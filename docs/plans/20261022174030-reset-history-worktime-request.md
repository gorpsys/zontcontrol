# Постановка: история сброса и приоритет меток worktime

Дата: 22.10.2026.
Статус: требования владельца согласованы 22.10.2026; реализация в работе.

Исходный запрос:

> тогда plan-writer
> для учёта статуса переключателя "сброс котла" искать в истории последнее его значение не ограничиваясь 45 минутным интервалом. Для этого статуза - делать запрос за 2 часа.
> Для worktime в случае противоречивых данных - приоритет за абсолютным значением времении перед дельтой.

Контекст расследования:

- Вызов 22.10.2026 16:30 МСК дал unknown. В его 46-минутном запросе не было
  ни одной отметки reset; предыдущая отметка OFF была в 15:38:54 МСК.
  На позднее прочитанной истории результат reset_state_unknown воспроизведён.
- В исследованной истории reset неизменный OFF повторяется примерно раз
  в час; изменения ON/OFF имеют отдельные секундные отметки. Архив сам
  по себе не доказывает задержку публикации этих записей в API.
- Ответ ZONT содержит worktime=60 и worktime=0 на 16:41:00 МСК.
  Значение 60 передано отрицательной временной дельтой, 0 — абсолютной
  меткой 1792676460. Оба времени уже целочисленные в ответе сервера;
  клиент доли секунды не обрезает.
- Точная причина исходного unknown в 16:46 не установлена: исходный
  ответ вызова не сохранён. Поздняя история даёт normal; без последней
  температурной минуты — unknown после конфликта worktime.

Локальные материалы исследования, не обязательные для выполнения плана:
reports/unknown-replay-2026-10-22/ и reports/reset-switch-history-2026-10-22/.
