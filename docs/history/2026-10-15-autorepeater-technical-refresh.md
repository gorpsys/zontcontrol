15.10.2026. По запросу владельца повторно проверен
[gorpsys/autorepeater](https://github.com/gorpsys/autorepeater) на master,
SHA [49cb338daae8d808706ec9d2480ca3f21ea4dcfd](https://github.com/gorpsys/autorepeater/commit/49cb338daae8d808706ec9d2480ca3f21ea4dcfd).
Архитектура отопления и бизнес-решения стороннего приложения не переносились.

Основные источники на этом SHA: AGENTS.md, docs/agents/development.md,
docs/agents/deployment.md, scripts/README.md, scripts/release_version.py,
.github/workflows/python-app.yml и .github/workflows/release-tag.yml.

## Перенесённые правила

- Версия X.Y.Z явно объявляется в zontcontrol/__init__.py и совпадает с первым
  разделом выпуска CHANGELOG. Номер, дата, ссылка и список изменений
  проверяются до сборки/установки runtime. Исходники, CLI и wheel имеют один номер.
- Обязательный Offline checks проверяет, что версия выше существующих тегов
  и CHANGELOG базы PR, даже если предыдущий тег ещё не создан. Компоненты
  сравниваются как числа. PR имеет только read-права; checkout точного SHA.
- После слияния Release tag публикует аннотированный vX.Y.Z на SHA мержа.
  Только этот job получает contents:write. Очередь release-tags сохраняет
  ожидающие задания (cancel-in-progress=false, queue=max).
- Аннотация берётся из CHANGELOG. Повтор того же SHA идемпотентен, другой
  SHA или lightweight тег дают ошибку; force/перенос/удаление тегов не применяются.
  Позднее задание не теряет свой тег из-за более нового тега потомка.
- При неуспехе повторяется исходный run с исходным SHA. Workflow dispatch
  на master проверяет текущий master. Тег не подтверждает production и
  не является триггером деплоя.
- Технические скрипты, CI и оформление сами по себе относятся к PATCH;
  смешанный выпуск классифицируется по изменениям приложения. Новые PR
  повышают номер относительно базы; прежние исторические пакеты не служат
  обходом нового gate.
- Будущий deploy сохраняет отдельную очередь с queue=max, проверяет
  происхождение checks и тот же SHA повторно перед OIDC. Идентификаторы
  autorepeater и его credentials не копируются.

## Адаптация

Начальный номер 0.1.0 подготовлен локально как первый кандидат. Существующий
Git-derived _version.py удалён; dynamic metadata setuptools берёт литерал
пакета без импорта транспорта. Новых runtime/dev зависимостей не добавлено,
офлайн-тесты остаются unittest. SDK/vendor/runtime-lock и торговая Sandbox
E2E-обвязка autorepeater этому проекту не нужны и не копировались.
Наличие Pylint/Mypy/coverage-порогов стороннего проекта не выдаётся за
реально настроенные проверки zontcontrol: здесь lint проверяет синтаксис,
ссылки и метаданные. Пороги/инструменты нельзя объявлять выполненными без
их реализации и отдельной проверки применимости.

Дополнительно закрыты границы, важные для этого первого выпуска: публикация
самого первого корневого коммита без HEAD^, отказ при незакоммиченных файлах
версии и проверка отсутствия lightweight-тега при повторном запуске.
Проверка wheel обнаружила старый _version.py в build/lib после удаления
из исходников; make package теперь сначала очищает генерируемые результаты.
Тесты используют только временные локальные репозитории и bare remotes,
не GitHub или ZONT. Локальная папка zontcontrol пока не Git-репозиторий;
remote, защита master, Actions, реальные теги и деплой не создавались.

Порядок для пользователя — [технический README](../../scripts/README.md#версии-и-выпуск),
действующие инструкции — [разработка](../agents/development.md).
