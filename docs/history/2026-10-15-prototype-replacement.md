# Замена прототипа без обратной совместимости

15.10.2026. Решение владельца при разборе четвёртого замечания
[холодного ревью плана](../reviews/2026-10-15-architecture-alignment-plan.md).

Цель проработки — заменить сделанный прототип новым структурированным
решением. Старый клиент разбирается на модули согласно архитектуре и в
прежнем виде перестаёт существовать. Обратная совместимость не нужна:
старые Python API, сигнатуры, CLI-флаги, JSON и entrypoints не сохраняются
как обязательные контракты. Legacy/deprecation-адаптеры не создаются.

В плане закреплено:

- Авторизация/выдача токена, HTTP, адаптация ZONT и потребительский фасад
  разделяются; новый controller не строится поверх монолитного ZontClient.
- После переноса удаляются client.py/ZontClient/apply_command и cli.py/control.py.
  Новый application обслуживает zontcontrol и python -m zontcontrol;
  прежний entrypoint zontcontrol-control удаляется.
- Постоянный boiler_cli управляет только через новый фасад и действующую
  монополию. Отдельная утилита токена использует auth, скрипты — read API.
- Тесты переносятся по ответственностям. Сохраняются проверенные свойства
  данных, обработка ошибок, калибровка детектора и сценарии монополии;
  проверки отменённых контрактов заменяются. Сохранение старого клиента
  ради тестов и тесты обратной совместимости не нужны.
- Между TDD-этапами ещё не перенесённый исходный код может оставаться,
  но промежуточная сборка не объявляется завершённым продуктом. К завершению
  этапа 15 удалены старые пути, импорты, экспорты и fallback; этап 16 проверяет
  состав установленного wheel и новые интерфейсы.

Это решение также заменяет ранее записанные обещания сохранить старые
CLI-флаги, JSON и совместимый control --execute. Фиксированные конфиги
каждого алгоритма и прочие согласованные правила архитектуры сохраняются.
Предварительный отказ legacy apply_command с понятной ошибкой не нужен:
сам метод и его старый клиент отсутствуют в итоговом продукте.

Замечание №4 закрыто обновлением
[архитектуры](../agents/architecture.md) и
[плана](../plans/completed/20261015005915-architecture-alignment-implementation-plan.md).
Все четыре замечания плана разобраны: №1 и №3 уточнены решениями, №2 снято
исправлением неверного требования к continuous, №4 заменено полным удалением
прототипа. Реализация пока не начата; код и устройство не изменялись.
