# Удаление синхронизации управления

20.10.2026 владелец решил удалить всю синхронизацию управления прибором,
включая локальную. Критерий успеха — код стал проще. Это решение заменяет
прежние требования монополии, лидера, аренды и обмена R1/R2.

Основание — [измерения одиночных чтений](../reports/2026-10-19-read-frequency.md):
таймауты встречались и с паузами 20/30/60 с, явных HTTP 429 не было.
Владелец предположил влияние качества сети и не увидел практической ценности
такой координации при наблюдавшихся задержках. Причина ошибок не доказана;
это продуктовое решение об упрощении, а не утверждение о rate limit ZONT.

## Что удалено

Пакет coordination с Fischer/lease/grants, строки R1/R2, профили безопасности,
локальный CommandExecutor с монополией на прибор, очередь асинхронных запросов,
сессии, consumer bindings, cleanup workers и статистика оркестрации.
Удалены относящиеся к ним поля конфигов, скрипты калибровки/анализа и тесты
отменённого протокола. Нет выключенного режима, no-op acquire или legacy API.

Controller API v2 предоставляет execute_command(command): актуальная проверка
capabilities/online, затем один сетевой send. Предпросмотр и фактические
команды по-прежнему разделены. Несколько потребителей могут одновременно
отправлять команды одному прибору; приложение не разрешает их конфликты.
Управляющий модуль больше не читает/пишет name/notes для координации и не
очищает прежние значения на реальном приборе автоматически.

## Что сохраняется

API чтения/истории/списка управления, несколько приборов на ЛК, DI и потоки
алгоритмов, их независимость и конфиги. Семь методов Controller заменяют
тринадцать прежних методов. Проверки данных и калибровка детектора неизменны.
CLI сохраняет preview/--execute, allowlist и графики.
Сброс сохраняет проверку текущей аномалии, защиту уже включённого переключателя,
импульс 40 с, off в finally и паузу 5 минут в continuous.

Удаление локальной монополии не означает удаления потокобезопасности
состояния регистратора или терминала. Они не сериализуют команды прибору.
Shutdown ждёт finally собственных алгоритмов, затем закрывает транспорт.
Отдельного отслеживания внешних команд больше нет: внешний caller завершает
свои вызовы до app.close(). Kill/смерть host по-прежнему вне гарантии finally.

## Переход

Из controller.json удалены coordination/statistics, из CLI — lease_seconds и
grant_wait_seconds, из reset — grant_wait_seconds/grant_poll_seconds.
Старые параметры не игнорируются загрузчиком; пользовательские ID и графики
сохранены. Рабочие конфиги остаются вне Git. Новых зависимостей и сервисов нет.
Реальная отправка команд, очистка полей ZONT и деплой не входят в офлайн-проверку.

Ранее выполненные планы и отчёты остаются историей и не описывают текущий код.
Актуальны [архитектура](../agents/architecture.md) и [контракты](../agents/contracts.md).

## Результат и проверки

Production Python-код относительно HEAD ветки до удаления: 39 файлов и
7323 строки → 26 файлов и 3670 строк. Удалено 3653 строки, около 50%.
Уменьшение не включает удалённые скрипты, тесты и документацию.

При повторном ревью дополнительно удалены UUID запусков и их DI, фабрика
consumer-контроллера, закрытие ресурсов из runtime, per-call HTTP-бюджет,
параметр fields без потребителей и эмуляция дрейфа часов в тестах.
Ресурсами владеет application/registry; runtime отвечает за один запуск.
Три справочника отменённой координации перенесены в docs/history;
актуальные zont-api и anomaly-detection исправлены на прямое управление.

make check: 298 тестов, успешно; четыре installed-only пропуска.
make package-check: шесть тестов установленного wheel, все успешны без пропусков.
Проверены прямые команды без сессии, повторная проверка preview, отсутствие
сериализации одного прибора, unknown без повторов, off после отмены/долгого
ожидания, shutdown с finally, сохранение unknown истории и отсутствие старых
модулей в исходниках/пакете. Детектор, monitor и detection_profile не менялись.
Физические команды и очистка полей реального ЛК не выполнялись.
