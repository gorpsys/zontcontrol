# Собственная конфигурация алгоритмов

15.10.2026. Решение владельца при разборе третьего замечания
[холодного ревью плана](../reviews/2026-10-15-architecture-alignment-plan.md).

Конфигурация — внутреннее дело алгоритма, включая CLI. У каждого алгоритма
фиксированное имя файла в каталоге конфигов проекта. Для текущих модулей
это config/boiler_reset.json и config/boiler_cli.json. Чтение, схема,
валидация и ошибки принадлежат самому модулю.

Регистратор читает только свои настройки из config/registry.json:
запрещённые модули, автозапуск и minimum/recommended once timeouts.
module_configs из него исключён. Общий управляющий модуль использует
config/controller.json для транспорта, координации и статистики; алгоритмы
получают его API через DI. Секреты остаются в окружении, не в JSON.

План фиксирует каталог config/ относительно cwd корня проекта для checkout
и установленного wheel, без поиска вверх по дереву и без общих --config
или ZONT_CONFIG. Примеры копируются в фиксированные рабочие имена;
отсутствующий обязательный файл даёт понятную ошибку с путём до сетевых действий.
В тестах чтение/путь подставляются обычными зависимостями. Запрещённый модуль
не читает свой конфиг. Конфиг постоянного алгоритма перечитывается при start;
автоматический reload не требуется.

Для совместимости старый control --execute использует конфиг CLI через
его модуль без запуска регистратора. Сохраняются явные флаги контакта и
HTTP-таймаута: --contact, затем ZONT_CONTACT, затем controller.json;
явный --timeout, затем controller.json, затем прежние 15 с. Это собственные
правила адаптера CLI, не глобальная система переопределения настроек алгоритмов.
Предпросмотр/help/version сохраняют независимость от конфигов, токена и сети.
