### Отключение повторов timer v2

План (строки 65 и 273 на момент проверки) и справочник yc (строки 241–246)
задают присутствующий retry_policy с retry_attempts="0" и утверждают, что
это отключает повтор управляющего once-запуска.

[Официальный protobuf v2](https://github.com/yandex-cloud/cloudapi/blob/master/yandex/cloud/serverless/triggers/v2/trigger.proto)
задаёт RetryPolicy.retry_attempts диапазоном 1–5. Action.retry_policy при
этом обозначен optional. Это расхождение с опубликованным контрактом,
но оно само по себе не доказывает отказ API: proto3 scalar zero/default
может обрабатываться отдельно, присутствие нуля в JSON не доказывает наличие
его значения после protobuf-декодирования.

Не подтверждено и утверждение, что отсутствие всего блока retry_policy
гарантирует отсутствие повторов. [Инструкция создания таймера](https://yandex.cloud/ru/docs/functions/operations/trigger/timer-create)
называет политику необязательной, но не объясняет это поведение явно.
Default старого CLI нельзя автоматически переносить на action v2.

Возможное последствие: команда не создаст таймер либо политика повторов
всего управляющего запуска будет отличаться от ожидаемой. Реальный отказ
или повторный вызов в этом ревью не наблюдался.

Минимальная рекомендация: считать схему отключения повторов открытым
вопросом до подтверждения её семантики. После подтверждения согласовать
action JSON, read-only проверку metadata и офлайн-тесты с этой семантикой.
Автоматически заменять ноль отсутствующим блоком без доказательства не следует.

Проверка основным агентом: диапазон 1–5 и optional-блок подтверждены по
официальному protobuf. Неопределённость поведения нуля/отсутствующего блока
сохранена; утверждения о доказанном отказе API или гарантированном no-retry
не сделаны. Вопрос применим: отключение повторов заявлено самим планом.

Проверены граф импортов и allowlist once-архива, API результата/cleanup,

Файлы субагентом не менялись. Реальных cloud/ZONT-запросов, изменений
ресурсов или запуска WunderReview не было. Основной агент сохранил отчёт;
план по результатам этой итерации пока не изменён.

## Последующее решение владельца

Владелец поручил использовать повторы как у autorepeater. План и справочник
команд обновлены: retry_attempts=1, interval=10s в action таймера, без явного
--async-max-retries при публикации версии функции. Повтор выполняет весь
once и может снова инициировать сброс; отсутствие флага не выдаётся за
гарантию отсутствия повторов платформы.

Открытый вопрос о схеме отключения повторов снят изменением требования:
отключение больше не требуется. Семантика нуля/отсутствующего блока этим
решением не доказана. Новая политика соответствует ранее прочитанной
конфигурации таймера образца и допустимому диапазону protobuf v2.
Изменён только план; реальные облачные настройки не менялись.
