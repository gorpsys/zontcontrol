# История изменений

## Не выпущено

## [0.7.0](docs/agents/contracts.md) - 2026-10-21

- Публичный Controller предоставляет чтение и замену notes выбранного устройства.
- Облачный handler сохраняет точный лог вызова в notes: новый запуск первым,
  за ним два предыдущих. Ошибка сохранения не повторяет работу алгоритма.

## [0.6.0](docs/agents/contracts.md) - 2026-10-21

- Любой клиент отмечает первое подключение к выбранному прибору заменяемым
  суффиксом времени UTC в его названии, сохраняя исходное имя.
- Облачный ответ содержит подробную оценку детектора и безопасный лог вызова;
  при ошибке тот же лог возвращается в JSON сообщения RuntimeError с сохранением повторов.

## [0.5.2](docs/agents/deployment.md) - 2026-10-21

- Загрузка ZIP использует готовый метод autorepeater: обычный путь --body,
  окружение yc с YC_IAM_TOKEN и явный временный профиль без лишних флагов.
- Ошибка upload останавливает деплой без повторов и дополнительного HEAD;
  проверки master, целевой функции, Lockbox и результата создания сохранены.
- Успешный облачный деплой этим исправлением ещё не подтверждён.

## [0.5.1](docs/agents/deployment.md) - 2026-10-21

- Диагностика деплоя различает GitHub checks API, GitHub OIDC и Yandex IAM,
  сообщает exit-код yc и фиксированную категорию ошибки без ответов провайдера.
- При неизвестном исходе upload сохраняются безопасная причина и результат
  контрольного HEAD; повтор записи и создание версии функции запрещены.
- OIDC-документация приведена к подтверждённому immutable subject репозитория.
  Первый успешный deploy, таймер и облачная приёмка ещё не подтверждены.

## [0.5.0](docs/plans/completed/20261020165020-yandex-cloud-boiler-reset-implementation-plan.md) - 2026-10-20

- Добавлены облачный handler для одного boiler_reset once, отдельный профиль
  и минимальный ZIP с manifest и офлайн-проверкой вне checkout.
- Внутренний каталог больше не экспортирует eager-константу BUILTIN_SPECS.
  Для явной локальной композиции использовать builtin_specs(), для once —
  (BOILER_RESET_SPEC,); create_application() сохраняет локальные defaults.
  [Переход](docs/agents/architecture.md#3-регистратор-и-запуск).
- GitHub Actions готовит деплой проверенного master через OIDC и pinned Lockbox,
  проверяет происхождение SHA, параметры функции и результат публикации.
- Локальные и облачные входы используют безопасное логирование; JSON stdout
  сохраняет статусы unknown/suppressed и не раскрывает API-ошибки и credentials.
- Controller API v2, профиль детектора, импульс 40 с и off в finally сохранены.
  Ресурсы подготовлены; первый deploy, включение таймера и облачная приёмка
  ещё не выполнены. Версия исходников не означает активацию плановых сбросов.

## [0.4.0](docs/reports/2026-10-20-typed-heating-regressions.md) - 2026-10-20

- Monitor принимает неизменяемую HeatingHistory; Controller API v2 и архивы
  преобразуются отдельными адаптерами без промежуточной JSON-формы в runtime.
- Фактические температуры линейно интерполируются на минутную сетку по точным
  датам соседних измерений с интервалом до 120 с. Без правой опоры конец сетки
  сдвигается максимум на минуту; неизвестные значения не экстраполируются.
- BoilerReset читает 46 минут для прежнего 45-минутного прогона детектора.
  Профиль и пороги, импульс 40 с, off в finally и пауза 300 с сохранены.
- Все исследовательские вызовы переведены на предметную историю. Удалены
  history_packet и прежние сигнатуры monitor без совместимых aliases.
- Сохранены полные синтетические регрессии; различия 704 архивных окон и
  охват дополнительных локальных проверок описаны в отчёте. Новая нормализация
  может менять решения; прежняя калибровка не выдаётся за полный новый прогон.

## [0.3.0](docs/history/2026-10-20-remove-synchronization.md) - 2026-10-20

- Удалены межклиентская синхронизация и локальная монополия управления:
  лидеры, аренды, R1/R2, grants, очереди разрешений и персональные sessions.
- Controller API v2 исполняет execute_command(command) напрямую после актуальной
  проверки возможностей/online. Автоповторов неизвестных команд нет.
- CLI и boiler_reset используют тот же прямой API. Preview/--execute,
  калиброванный детектор, импульс 40 с и off в finally сохранены.
- Конфиги лишились coordination/statistics/lease/grant; рабочие ID и графики
  сохранены. Удалены скрипты и тесты отменённого протокола; добавлены проверки
  прямого управления, параллельных команд и shutdown с finally.
- Удалены оставшиеся UUID запусков, фабрика consumer-контроллера, отдельное
  закрытие ресурсов runtime и индивидуальные HTTP-бюджеты координации.
  Текущие справочники описывают прямой API, прежний протокол перенесён в историю.
- Переход требует удаления старых параметров по config/README.md; совместимых
  заглушек прежнего API монополии нет. Деплой и команды реальному котлу не выполнялись.

## [0.2.1](docs/history/versioning.md) - 2026-10-17

- Межклиентская координация собрана в zontcontrol.coordination: ленивый
  runtime и worker перенесены из application, зависимости задаются через
  структурные порты и статическую поверхность пакета. Application собирает
  зависимости и закрывает ресурсы в прежнем порядке.
- Общие ошибки и ControlSession вынесены в control_types и реэкспортируются
  контроллером как те же объекты. Документированы граница пакета и поздняя
  фабрика worker в composition root.
- Структурный перенос сохраняет Controller API v1, wire v1, алгоритм R1/R2,
  сроки, наблюдения и принятые риски; новых пользовательских функций нет.
  Проверка офлайн, без измерения надёжности ZONT и реального управления.
- Дополнены аннотации сборки приложения, конфигурации, контрактов, исполнителя
  и координации. Генератор UUID передаётся через DI для воспроизводимых
  офлайн-проверок запросов, grant, сессий и запусков; по умолчанию остаётся uuid4.
  Позднее разрешение фабрики coordinator пояснено непосредственно в коде.
- В тестах UUID задаются отдельным потокобезопасным mock-генератором на сценарий.
  Проверены конкретные ID при передаче через DI, запросе/продлении монополии
  и перезапуске алгоритма, а также отсутствие лишней генерации при опросах.

## [0.2.0](docs/history/versioning.md) - 2026-10-17

- API v1 дополнен request_control/get_control_request/cancel_control_request
  и синхронным acquire_control: запрос самостоятельно ожидает монополию,
  возвращает неизменный результат GRANTED/DENIED и безопасный error_code.
  try_acquire_control сохраняет непосредственную попытку без ожидания grant.
- Timeout и аренда считаются от создания запроса, очередь и опрос не продлевают
  срок. Отмена и shutdown не раскрывают позднюю session; принятый HTTP
  завершается с cleanup, неизвестный release не повторяется.
- CLI ожидает grant при первом --execute; необязательный grant_wait_seconds
  по умолчанию равен min(30, lease_seconds/2). boiler_reset использует тот же
  acquire_control, сохраняя свои интервалы, бюджет импульса и finally.
- Terminal handles хранятся слабо, workers завершаются после очистки очереди;
  shutdown дожидается принятых попыток и cleanup до закрытия транспорта.
- Документированы принятые риски R/L/A и запрещённые регрессии C, границы
  локальных deadlines и независимость ранее запущенного координатора.
  Изменение проверено офлайн; фактическая надёжность ZONT не измерена.

## [0.1.2](docs/history/versioning.md) - 2026-10-16

- Штатный close приложения закрывает новые привязки и захваты до отмены
  алгоритмов, ждёт их finally и все сессии общего исполнителя, включая внешних
  Python-потребителей, и только затем закрывает координацию и транспорт.
- Ограниченный close возвращает False с открытыми ресурсами до завершения
  cleanup; повторные и конкурентные вызовы ждут один shutdown. Ошибка раннего
  hook терминальна и возвращает безопасный RuntimeError без закрытия ресурсов.
- Документированы явный release внешнего владельца до полного close,
  ожидание сессий между командами и сохранённые ограничения аренды R2 и kill.
- Срок аренды ограничивает и локальную idle-сессию: после expiry она не
  блокирует следующий захват или shutdown. Выполняющиеся вызовы завершаются;
  прерывание получения контекста статистики больше не оставляет вечную блокировку.
- Уточнены имена состояния shutdown, общая проверка expiry и тестовые фикстуры.

## [0.1.1](docs/history/versioning.md) - 2026-10-16

- Служебный индикатор питания Widget API с ID 0 больше не блокирует каталог
  и чтение настоящих датчиков с адресуемыми ID.
- Единицы температурных датчиков «°» нормализуются в °C, как у целей контура,
  чтобы фактические и целевые температуры можно было показать на одном графике.
- Рабочие config/*.json исключены из Git; config/*.example.json остаются
  версионируемыми. Личные привязки и настройки не публикуются.

## [0.1.0](docs/history/versioning.md) - 2026-10-16

Первый продуктовый выпуск подготовлен одним PR от пустого master.
Это полная замена прототипа без совместимости прежних Python/CLI/JSON;
версия не означает уже опубликованный тег или деплой.

### Управление и алгоритмы

- Реализован API v1: явная адресация приборов/элементов, неизменяемые DTO,
  типизированные ошибки, чтения текущих значений и частей истории с честным
  покрытием, null и неизвестным временем измерения.
- Команды требуют собственной монополии на целый прибор; синхронный ответ API,
  явная ошибка и неизвестный исход после отправки различаются. Принятые команды
  завершаются независимо от stop/timeout; автоматических повторов нет.
- Добавлены условный Fischer + lease и обмен R1/R2, относительные сроки,
  clock_rho, индикация занятости в name и JSONL-наблюдения. Известные гонки
  приняты со сбором статистики; строгая безопасность и 99.9% не доказаны.
- Регистратор/DI управляет once/continuous в потоках одного процесса.
  Timeout once, кооперативный stop и stopping сохраняют finally и монополию;
  continuous задаёт свои интервалы и таймауты.
- boiler_reset при текущем confirmed_pattern выполняет реальный импульс 40 с,
  немедленно пытается выполнить off в finally; continuous ждёт пять минут
  после off. Общего execute-флага, guard, watchdog и recovery-журнала нет.
- boiler_cli показывает текущие значения с quality, ручной preview/--execute
  и SVG-графики на stdlib. Прямой ЛК сохранён с ответственностью человека.
- Сохранён детектор SMART 2.0 с unknown/suppressed и прежней калибровкой:
  десять известных отказов обнаружены на 83 днях архива; это не независимая
  проверка будущих отказов.

### Запуск и разработка

- Новый application root: list, once, all, start, host; Python API также
  поддерживает stop/close в том же процессе. Старые client.py, cli.py,
  control.py, apply_command и zontcontrol-control удалены без legacy-адаптеров.
- Фиксированные cwd/config/controller.json, registry.json и собственные
  config-файлы модулей, токен только через окружение. Конфиги и примеры
  не включены в wheel; read root не запускает регистратор и координатор.
- Скрипты истории используют новый API; analyze_history строит три SVG
  на stdlib. Runtime Python 3.11+, без внешних библиотек.
- Офлайн-тесты включают виртуальные устройства, часы, конкурентные сценарии,
  калибровку, CLI и smoke установленного wheel вне checkout.
  CI проверяет Python 3.11/3.12; make package-check объединяет сборку и smoke.
- Явный __version__, проверка версии относительно базы PR/тегов и workflow
  аннотированного тега на будущем SHA мержа; завершение плана тег не создаёт.
- Cloud handler, ZIP, OIDC/Lockbox и деплой остаются будущей работой.
