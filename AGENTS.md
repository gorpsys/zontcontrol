# zontcontrol

Приложение ZONT: управляющий API, разовые и постоянные алгоритмы, ручной CLI.
Использование — [README](README.md), общая карта — [документация](docs/README.md).
Перед изменениями выбрать область в [индексе инструкций](docs/agents/README.md).

## Порядок работы

1. Соблюдать [границы модулей](docs/agents/architecture.md#1-состав-и-границы):
   транспорт, нормализация, чистый детектор, команды и UI разделены.
   Потребители используют [Controller API v2](docs/agents/contracts.md#управляющий-api),
   все адресные операции явно задают device_id.
2. Не возвращать распределённую или локальную монополию прибора: мьютекс,
   лидера, аренду, sessions/grants, очереди или координацию через name/notes,
   включая guard/executor/binding и совместимые заглушки. Разные клиенты
   могут вмешиваться одновременно. UTC-отметка name и три cloud-лога в notes —
   диагностика по [контрактам](docs/agents/contracts.md#управляющий-api)
   и [облачному входу](docs/agents/contracts.md#облачный-вход).
   Основание — [решение 20.10.2026](docs/history/2026-10-20-remove-synchronization.md).
3. Отделять preview от отправки: CLI отправляет только с --execute,
   execute_command повторно проверяет возможности/online и отправляет одну
   команду без автоматического повтора. Соблюдать
   [сброс on → 40 с → off в finally](docs/reference/boiler-reset.md#назначение-и-последовательность),
   [остановку и границы гарантии](docs/reference/boiler-reset.md#остановка-и-ошибки),
   [интервалы](docs/reference/boiler-reset.md#интервалы).
   API-успех не доказывает физический результат.
4. Сохранять обычный DI, потоки одного процесса и
   [lifecycle регистратора](docs/agents/contracts.md#автономные-алгоритмы).
   Stopping/finally запрещает повторный старт того же алгоритма; служебные
   locks не дают права управления прибором. [Shutdown](docs/agents/contracts.md#завершение)
   ждёт finally до закрытия транспорта; внешние вызовы завершает потребитель.
5. Использовать фиксированные [конфиги](config/README.md), без общих
   --config/ZONT_CONFIG. Рабочие JSON вне Git. Токен локально — ZONT_TOKEN,
   в облаке — Lockbox. Секреты не сохранять в коде, документации, логах
   и аргументах; произвольные API-ошибки не выводить.
6. Сохранять «Отопление», реальные timestamps, null/пропуски и unknown.
   [Детектор](docs/reference/anomaly-detection.md) и калибровку не менять под
   видом реорганизации или удаления синхронизации; пороги требуют обоснования
   и проверки. Старые контракты заменённого прототипа не восстанавливать.
7. Правки через apply_patch с сохранением чужой работы. Runtime — stdlib,
   новые зависимости согласовывать. Проверки — unittest, make check;
   при изменении состава пакета — make package-check по
   [правилам разработки](docs/agents/development.md#проверки).
   Офлайн-проверки не вызывают ZONT и облако.
8. Размещение, источники, статусы и архивирование задают
   [правила документации](docs/agents/documentation.md).
   SemVer, совпадение __version__/CHANGELOG и один выпуск на PR — по
   [процедуре выпуска](scripts/README.md#версии-и-выпуск).
   Вручную теги не публиковать и не переносить. Merge — только по отдельному
   запросу владельца.

## Облако

Yandex Cloud Functions запускает boiler_reset once по
[контракту деплоя](docs/agents/deployment.md); процедура —
[how-to](docs/reference/github-yandex-cloud-howto.md), свидетельства —
[приёмка](docs/reports/2026-10-21-yandex-cloud-acceptance.md).
Соблюдать разделение отдельных и общих ресурсов; исходные ресурсы autorepeater
не менять. Каждый ручной запрос yc отдельно подтверждается владельцем;
согласованный автоматический workflow не требует подтверждений каждой команды.
Создание/включение таймера требует первого успешного деплоя и отдельного
подтверждения владельца. Сборка, CI и план не означают активацию.
