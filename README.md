# zontcontrol

Клиент отопления ZONT: читает датчики и цели температур, получает историю,
обнаруживает отсутствие нагрева и подготавливает команды управления.
Проверен с ZONT SMART 2.0. Python 3.11+, сторонних runtime-библиотек нет.

Сейчас работает локальный CLI. Автоматическое восстановление и облачный
запуск находятся в [плане](docs/plans/yandex-cloud.md).

## Установка

Из каталога проекта можно запускать python3 -m zontcontrol. Для установки
CLI в отдельное окружение:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/zontcontrol --help
.venv/bin/zontcontrol --version
```

Далее показан запуск из каталога проекта. После установки вместо
python3 -m zontcontrol можно использовать команду zontcontrol.

## Токен и контакт

Если токена ещё нет:

```sh
python3 -m zontcontrol.get_token --contact YOUR_EMAIL
```

Утилита запросит логин и пароль ZONT, создаст новый токен и выведет его
на экран. Пароль вводится скрыто; пароль и токен в файлы не записываются.
Для существующего токена в ~/.tokens/zont:

```sh
export ZONT_TOKEN="$(cat "$HOME/.tokens/zont")"
export ZONT_CONTACT='YOUR_EMAIL'
```

ZONT_CONTACT — контакт для заголовка X-ZONT-Client, он может отличаться
от логина. Вместо переменной можно передать --contact.
Основной клиент читает токен только из ZONT_TOKEN. Если его нет, завершает
работу с инструкцией и не обращается к API. Токен не передавайте через
аргументы или коммиты. --help и --version работают без токена.

## Датчики и список устройств

```sh
python3 -m zontcontrol
python3 -m zontcontrol --device-id 700877
python3 -m zontcontrol --list-controls --device-id 700877
```

Первый запуск показывает устройства и их ID. Примеры здесь используют
текущий SMART 2.0 владельца; для другого прибора подставьте свои ID.
Контур «Отопление» — 20496: target_temp означает цель воздуха,
setpoint_temp — расчётную цель воды. Скрытый «Котел» тоже возвращается API,
но его цели не подставляются вместо целей выбранного контура.

Результат — JSON. null означает отсутствие значения, а не ноль.
fetched_at — время получения ответа, а не измерения; online и status=ok
не гарантируют свежесть показания. Подробнее — [форматы API](docs/reference/zont-api.md).

## История

Последние сутки для «Отопление»:

```sh
python3 -m zontcontrol --history --hours 24 --device-id 700877 --circuit-id 20496
```

Фиксированный период:

```sh
python3 -m zontcontrol --history --device-id 700877 --circuit-id 20496 --from '2026-10-12T10:00:00+03:00' --to '2026-10-13T10:00:00+03:00'
```

Дата требует часовой пояс. --from и --hours вместе не используются.
Для истории переключателей добавить --include-controls.
Результат содержит временные точки датчиков и ряды выбранного контура;
time_truncated означает, что сервер сократил диапазон.

## Проверка нагрева

```sh
python3 -m zontcontrol --detect-anomalies --device-id 700877 --circuit-id 20496
```

Один запуск читает последние 45 минут с историей сброса и принимает
независимое решение на конец периода. Постоянный процесс не требуется.

| Состояние | anomaly | Значение |
| --- | --- | --- |
| normal | false | Текущих признаков по порогам нет |
| warning | true | Есть подозрение на отсутствие отклика |
| confirmed_pattern | true | Условия подтверждения температурного паттерна выполнены |
| suppressed | false | Намеренное отключение или пауза запуска после сброса |
| unknown | null | Данных недостаточно для решения |

Основные поля: state_at_period_end, anomaly и decision_reason.
События events описывают прочитанное окно: старое событие не означает,
что аномалия продолжается сейчас. normal не гарантирует исправность котла.

Профиль SMART 2.0 учитывает предел котла 85 °C, средний запрос worktime,
недогрев воды от 4 °C и отсутствие отклика 13 минут при воде <=60 °C,
14 минут при более горячей воде. Воздух должен быть не выше цели ИЛИ
вода должна остыть от начала наблюдения минимум на 3 °C.
Стабильная горячая вода исключается. Сброс подавляет проверку и даёт
пять минут на запуск после переключения.

[Полный алгоритм](docs/reference/anomaly-detection.md) и
[результат калибровки](docs/reports/2026-10-13-anomaly-calibration.md).
Профиль подобран на известных данных; отсутствие будущих ложных сигналов
не гарантируется. Детектор только читает данные.

## Управление

Утилита управления по умолчанию показывает запрос и не обращается к API:

```sh
python3 -m zontcontrol.control set-temp --device-id 700877 --element-id 20496 --temperature 22
python3 -m zontcontrol.control activate-mode --device-id 700877 --element-id 20503
python3 -m zontcontrol.control set-switch --device-id 700877 --element-id 8832 --state off
```

Чтобы отправить подготовленную команду, добавьте --execute. Нужны
ZONT_TOKEN и ZONT_CONTACT либо --contact. Клиент предварительно проверяет
связь, элемент, команду и допустимый диапазон.

set-temp меняет цель воздуха и переводит контур в ручной режим.
Для возврата в расписание активируйте режим 20503.
У переключателя «Сброс котла» on означает «котёл отключён», off —
«котёл включён». Предпросмотр помечается dry_run=true; физическое действие
происходит только при отправке. Все команды и ограничения —
[справочник](docs/reference/zont-api.md#подготовка-и-отправка).

## При ошибке

- Нет токена: получить его утилитой и задать ZONT_TOKEN.
- 401/403: проверить доступ и действительность токена.
- 429: дать API паузу; основной клиент не повторяет запрос автоматически.
- unknown: проверить историю, свежесть температур, выбранный датчик и состояние сброса.
- Таймаут после отправки команды: сначала прочитать состояние и проверить
  прибор. Ошибка не доказывает, что команда не выполнена.
